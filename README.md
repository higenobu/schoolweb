# 大学総合管理システム開発仕様書  

---

## 1. 目的  
本システムは、大学全体の運営業務（学籍管理、財務・会計、人事・給与、施設管理、情報システム統合等）を一元的に管理し、業務効率化・データ可視化・意思決定支援を実現することを目的とする。

## 2. スコープ  
| 区分 | 内容 |
|------|------|
| 対象部門 | 学務課、財務課、人事部、総務課、図書館、ITセンター、研究室 |
| 対象業務 | 入学・卒業・在籍管理、履修・成績管理、予算編成・執行、給与計算、勤怠管理、資産・設備管理、情報共有・通知 |
| 非対象業務 | 個別教育プログラム開発、外部委託契約管理、研究助成金審査 |

## 3. 用語定義  
- **ユーザー**：システム利用者（教職員、学生、外部ベンダー）。  
- **ロール**：権限レベル（管理者、部署長、一般職員、学生）。  
- **マスタデータ**：学部・学科・教員・施設など、変更頻度が低い固定情報。  
- **トランザクションデータ**：日々生成される入退学、出納、給与計算等のデータ。

## 4. 機能要件  

### 4.1 共通機能  
1. **認証・認可**  
   - シングルサインオン（SAML/OIDC）対応  
   - 多要素認証（MFA）必須（管理者ロール）  
2. **UI/UX**  
   - レスポンシブデザイン、アクセシビリティ（WCAG 2.1 AA）  
   - カスタマイズ可能なダッシュボード  
3. **監査ログ**  
   - 全操作履歴を暗号化保存、検索・エクスポート機能  

### 4.2 学務系  
1. **入学・退学フロー**  
   - 書類自動受付、ステータス遷移管理  
2. **履修登録・成績管理**  
   - コースカタログ連携、GPA算出、成績公開制御  
3. **卒業判定**  
   - 必要単位・取得条件チェック、卒業証明書自動生成  

### 4.3 財務系  
1. **予算編成**  
   - 階層別予算設定、シミュレーション機能  
2. **会計処理**  
   - 仕訳自動生成、科目コードマスタ紐付け、月次・年次決算レポート  
3. **資金調達・補助金管理**  
   - 申請・承認ワークフロー、実績追跡  

### 4.4 人事・給与系  
1. **人事情報管理**  
   - 雇用契約、異動・昇格履歴、資格情報  
2. **給与計算**  
   - 法定控除自動計算、年末調整、給与明細PDF出力  
3. **勤怠管理**  
   - 打刻端末／モバイル打刻、休暇申請、残業承認フロー  

### 4.5 施設・資産系  
1. **施設予約・利用状況**  
   - カレンダー同期、リアルタイム空き確認  
2. **資産管理**  
   - 資産台帳、減価償却計算、棚卸し支援  

### 4.6 情報統合系  
1. **APIゲートウェイ**  
   - RESTful API（JSON）、OpenAPI 3.0 定義、OAuth2 認可  
2. **データ連携**  
   - ERP、LMS、HRIS との双方向同期（ETL バッチ／CDC）  
3. **通知サービス**  
   - メール、SMS、LINE公式アカウント、WebPush  

## 5. 非機能要件  

| 項目 | 要求内容 |
|------|----------|
| 可用性 | 年間稼働率 99.9%（障害復旧時間 ≤ 30 分） |
| パフォーマンス | 同時ユーザー 5,000 人まで、画面表示 < 2 秒 |
| セキュリティ | データ暗号化（AES‑256）、PCI DSS 準拠（財務データ） |
| スケーラビリティ | コンテナ化（Kubernetes）による水平スケール |
| バックアップ | 24 時間ごとの増分バックアップ、7 日間保持 |
| 法令遵守 | 個人情報保護法、学校教育法、労働基準法への適合 |
| 国際化 | 多言語対応（日本語、英語、中国語） |
| 運用性 | ログ集約（ELK Stack）、自動デプロイ（CI/CD） |

## 7. データモデル概要  

| エンティティ | 主な属性 | リレーション |
|--------------|----------|--------------|
| ユーザ | id, name, email, password_hash, role, department_id | 1:N → Role, Department |
| 学部・学科 | id, name, parent_id | N:M → Faculty, Department |
| 教員 | id, name, employee_id, faculty_id, title | N:1 → Faculty |
| 学生 | id, name, student_number, major_id, enrollment_status | N:1 → Major |
| 履修 | student_id, course_id, semester, grade | N:1 → Student, Course |
| コース | id, name, credits, instructor_id | N:1 → Instructor |
| 予算 | id, fiscal_year, amount, category, status | N:1 → FiscalYear |
| 会計仕訳 | id, period, debit, credit, account_code, memo | N:1 → Period |
| 資産 | id, asset_tag, description, value, depreciation_start, location_id | N:1 → Location |
| 勤怠 | id, employee_id, clock_in, clock_out, type, approved_by | N:1 → Employee |

## 8. インタフェース要件  

| 種別 | 接続先 | プロトコル | 主なデータ項目 |
|------|--------|------------|----------------|
| 外部ERP | SAP / Oracle EBS | SOAP / REST | 勘定科目、支払データ |
| LMS | Moodle | LTI 1.3 | コース情報、成績 |
| HRIS | Workday | SCIM, OAuth2 | 従業員マスタ、給与情報 |
| 学籍システム | 独自システム | CSV Import/Export | 入退学情報 |
| 通知サービス | Twilio, LINE Notify | HTTP API | メッセージ本文、送信先 |

## 9. テスト計画  

1. **単体テスト** – 各マイクロサービスのユニットテスト（JUnit, pytest） カバレッジ ≥ 80%。  
2. **結合テスト** – API契約テスト（Postman/Newman）およびデータ連携シナリオ。  
3. **性能テスト** – JMeter による同時接続 5,000 ユーザー負荷テスト。  
4. **セキュリティテスト** – OWASP ZAP による脆弱性診断、ペネトレーションテスト。  
5. **受入テスト** – UAT シナリオ（業務担当者） 100% 完了確認。  

## 10. 移行・導入手順  

1. 現行システムデータ抽出（CSV/DBダンプ）  
2. データクレンジング・正規化  
3. 新システムへロード（ETL ツール）  
4. ロールベース権限設定  
5. パイロット運用（限定学部） → フィードバック反映  
6. 本番切替（ブルー/グリーンデプロイ）  

## 11. 保守・運用  

- **障害対応**：SLA 1 時間以内初期応答、4 時間以内解決目標。  
- **定期メンテ**：月次パッチ適用、四半期バックアップ検証。  
- **バージョン管理**：GitFlow に基づくリリース管理、タグ付与。  
- **利用者サポート**：ヘルプデスク（メール・チャット）24/5。
